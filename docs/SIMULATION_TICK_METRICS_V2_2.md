# Hearthbound v2.2 — Simulation tick metrics and smoke stabilization

The autonomous scientist real-Minecraft scenario now reads `time query gametime` at research enablement, hypothesis proposal, haul completion, Create flour production and evidence-backed confirmation. It publishes `ticks_to_proposal`, `ticks_to_haul`, `ticks_to_first_flour` and `ticks_to_confirmation` alongside pre-existing monotonic wall-clock measurements.

Minecraft game ticks are a more useful basis for comparing learning policies across CI runner speed differences than wall time alone, although RCON polling introduces bounded timestamp uncertainty and non-deterministic entity behavior remains possible. Tick measurements require a successful game-time command; they cannot be silently fabricated.

Multi-seed aggregate reports calculate `mean_milestone_ticks` only from runs with recorded numeric measurements. Unit regressions ensure incomplete trials cannot be interpreted as successful and unavailable measurements are not substituted with zero. Generic smoke's delivery-position assertion now polls for up to 7.5 seconds to avoid an immediate snapshot race.

**Known remaining issue:** A separate intermittently empty RCON response during initial `sable haul` setup was observed in the v2.1 CI branch and is not explained by this proximity fix. Treat overall smoke as unverified until it passes. No gameplay video is generated by this workflow.
